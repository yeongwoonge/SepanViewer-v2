# 세판뷰어 v2 상세 사용 안내

DJMAX RESPECT V의 화면과 키 입력을 연결해 타이밍을 표시하고, 완료한 플레이의 통계를 저장하는 Windows 도구입니다.

[wtre/SepanViewer](https://github.com/wtre/SepanViewer)를 바탕으로 만든 비공식 수정본입니다. 원작자의 공식 후속 버전은 아닙니다. 현재는 테스트 버전이며 화면 기반 추정값을 제공합니다.

## 설치

1. Windows 11에 **Python 3.12 x64**를 설치합니다. Python Launcher도 포함합니다.
2. ZIP을 쓰기 가능한 폴더에 풀고 `install.bat`를 실행합니다. 처음 설치할 때는 인터넷이 필요합니다.
3. 설치가 끝나면 `start.bat`로 실행합니다.

Python 실행 환경은 ZIP에 포함하지 않습니다. 기록을 유지하려면 기존 폴더 전체를 삭제하지 말고 먼저 `records/`를 보관하세요.

## 처음 사용하기

1. 게임을 **1920×1080 또는 2560×1440, 전체 창 모드**로 실행합니다.
2. 세판뷰어 v2에서 게임 창과 **4 / 5 / 6 / 8** 버튼 수를 선택합니다.
3. **설정**에서 게임 판정 타이밍, 기어 위치, 키 배치를 실제 게임과 맞춥니다. 키 칸을 클릭하고 해당 키를 누르면 지정됩니다.
4. 기본 CYTUS 노트와 다른 노트를 쓴다면 **설정 → 노트·색 프리셋**에서 게임의 HUD 설정 화면 이미지를 불러오거나 Ctrl+V로 붙여넣습니다. 기어 폭과 노트 1·2의 영역, 사이드·트리거 색을 확인한 다음 적용합니다.
5. **시작**을 누르고 게임으로 돌아갑니다. 오버레이는 OBS 없이 게임 위에 표시됩니다.

배포 기본값은 **4키 / 가운데 기어 / 게임 판정 타이밍 0 / 기본 CYTUS 프리셋**입니다. 게임 판정 타이밍은 프로그램이 게임 설정을 읽어 자동으로 맞추는 값이 아니므로 직접 동일하게 입력합니다.

| 버튼 수 | 일반 노트, 왼쪽부터 | 사이드 | 트리거 |
|---|---|---|---|
| 4키 | S · D · K · L | 왼쪽 Shift / 오른쪽 Shift | — |
| 5키 | S · D · Space · K · L | 왼쪽 Shift / 오른쪽 Shift | — |
| 6키 | A · S · D · K · L · ; | 왼쪽 Shift / 오른쪽 Shift | — |
| 8키 | A · S · D · K · L · ; | 왼쪽 Shift / 오른쪽 Shift | Space / 오른쪽 Alt |

LS·RS는 좌우 사이드, LT·RT는 8키 트리거입니다. 버튼 수마다 키 설정을 따로 저장합니다.

## 게임에서 버튼 수 전환

측정을 시작한 뒤 게임 창에서 **Ctrl+Alt+4 / 5 / 6 / 8**을 누르면 해당 버튼 수와 저장된 키 배치로 전환합니다. 창을 전환할 필요가 없고 화면 자동 인식이나 외부 API를 추가로 사용하지 않습니다. 곡 선택 화면에서 사용하세요. 플레이 도중 누르면 진행 중인 시도가 초기화됩니다.

## 오버레이

**설정 → 오버레이 스타일·위치**에서 세로형과 기어 안 가로형을 선택합니다. 위치·크기·투명도를 조절할 수 있고 가로형은 기어에 맞춘 뒤 높이를 옮길 수 있습니다.

가운데는 흰색, ±42ms 경계는 옅은 금색으로 표시합니다. 가로형의 세 기준선은 입력 막대보다 길며 입력 표시 위에 그립니다. ±21ms 선은 옅게 유지합니다.

가로형은 왼쪽 FAST, 오른쪽 SLOW입니다. ±42ms 밖의 입력을 파랑·빨강으로 표시합니다. 최근 20회 입력의 표시가 입력 순서에 따라 흐려집니다. 현재 게임의 FAST/SLOW 글자를 직접 읽어 표시하는 기능은 아닙니다.

## 플레이 기록

결과 화면을 확인한 판만 자동 저장합니다. **F5는 진행 중인 시도를 초기화하며, 중도 재시작한 판은 저장하지 않습니다. 다만 결과 화면과 안전한 이미지가 이미 확인된 판은 F5 전에 완료 저장을 마칩니다.**

```text
records/
└─ 4K SC Away/
   └─ 2026-10-27_12-34-56/
      ├─ game-result.png
      ├─ timing.png
      ├─ summary.json
      └─ events.jsonl
```

곡명·난이도는 결과 화면에서 로컬 OCR로 읽습니다. 실패하면 ‘미확인’으로 두며 **최근 결과**에서 수정할 수 있습니다. 난이도 표기는 NM / HD / MX / SC입니다.

결과 이미지는 곡·판정·점수 등 필요한 영역만 저장하고 닉네임·프로필·개인 등급·포인트 영역은 제외합니다. 통계는 얼리·퍼펙·레이트와 타이밍 분포, 레인별 분포를 표시합니다. 기준선은 일반 ±42ms, 하드 ±21ms입니다.

결과 감지 전에 게임을 완전히 가리거나 최소화하면 저장을 확인할 수 없습니다. 이 경우 기록을 보류하므로 게임 결과 화면으로 돌아오세요. 이미 결과를 확보한 뒤 알트탭하거나 결과 영역이 다른 창에 가려지지 않으면 저장을 계속할 수 있습니다.

## 전체 통계

메인 화면의 **전체 통계**를 누르면 저장된 완료 기록을 버튼 수별로 모읍니다. **전체 통계 내기**로 최신 기록을 다시 집계하고, PNG 또는 통계 폴더를 열 수 있습니다.

- 입력 전체 평균: 모든 일반 입력을 합친 평균으로, 입력 수가 많은 판을 더 반영합니다.
- 판별 평균의 평균: 각 판의 평균을 구한 뒤 판마다 같은 비중으로 평균냅니다.
- 전체 평균과 분포는 측정 당시의 오차를 사용합니다. 서로 다른 게임 판정 설정의 기록도 포함합니다.
- 추천은 각 판의 추천값을 평균내지 않습니다. 같은 버튼 수·스킨·프리셋·판정선·캡처 빈도·보정 조건인 기록만 현재 게임 판정값 기준으로 환산하고, 합친 입력에서 ±42ms / ±21ms 안의 개수를 최대화합니다. 최소 2판·100입력이 필요하며 불안정한 기록은 추천에서 제외합니다.

통계는 클릭할 때만 백그라운드에서 계산하며 실시간 분석 루프에 작업을 추가하지 않습니다. 원래 기록은 수정하지 않고 `statistics/4K-overall.png` 같은 이미지와 JSON 요약을 별도로 만듭니다.

## 결과 화면과 페이드

결과 글자 두 영역을 초당 5회 확인하고 밝기가 안정된 뒤 이미지를 확정합니다. 보통 첫 감지 후 최소 1초와 밝기 안정 0.4초를 확인하며, 계속 움직이는 화면에서는 최대 2.5초 뒤 확보한 이미지로 마칩니다. 전체 화면 검사나 추가 OCR을 매 프레임 실행하지 않습니다. 알트탭 때는 이미 확보한 이미지 중 글자가 더 밝은 이미지를 보존하며, 너무 빨리 가리면 어두운 후보가 남을 수 있습니다.

## 추천 방식

한 판 후보는 ±42ms / ±21ms 안의 입력 수를 최대화하고 동률이면 경계에서 여유가 큰 값을 고릅니다. 전체 통계는 판별 범위 내 비율에 같은 비중을 주어 긴 곡 한 판의 영향이 지나치게 커지지 않게 합니다. 합계 퍼펙 수가 현재 설정보다 줄어드는 값은 선택하지 않습니다.

전체 추천은 판을 하나씩 제외하는 비교와 이전 판으로 다음 판을 예측하는 시간순 비교를 수행합니다. 입력 하나하나를 독립 실험으로 취급하지 않고, 확인용 판을 통째로 재표본해 이득의 흔들림을 확인합니다. 계산은 통계 생성 때만 수행합니다.

- 한 판 후보: 해당 판의 입력에서 찾은 값이며 다른 곡에 대한 검증은 없습니다.
- 잠정 후보: 기록이 적거나 시간순 비교의 이득이 아직 불확실합니다.
- 반복 기록 지지: 두 비교의 평균 이득이 양수이고 시간순 이득의 재표본 하한도 양수입니다. 최소 6판이 필요합니다.
- 현재 유지: 다른 기록에서도 개선될 근거가 부족하거나 이미 같은 값이 최적입니다.

최대 24개 확인용 판을 사용해 기록이 많아져도 계산량을 제한합니다. 재표본은 고정 시드라 같은 기록에서 결과가 무작위로 바뀌지 않습니다. 이는 화면 추정 모델에 대한 비교이며 실제 게임 RATE나 물리적인 1ms 정확도를 보증하지 않습니다.

## 지원 범위

- 실제 플레이 영상으로 확인한 범위는 주로 4키입니다. 5·6·8키는 합성 화면 검사를 거친 시험 기능입니다.
- 노트 이동과 누른 시각으로 타이밍을 추정합니다. 롱노트 유지·떼는 판정은 분석하지 않습니다.
- 스킨, 효과, 노트 가림, 캡처 주기에 따라 게임 판정과 차이가 날 수 있습니다. 모든 스킨을 자동으로 인식하거나 1ms 정확도를 보장하지 않습니다.
- 추천 판정은 ±42ms / ±21ms 안에 들어오는 입력 수를 최대화한 후보입니다. 게임 설정에 자동 적용하지 않습니다.
- 목표 캡처 빈도는 60fps이며 실제 처리 속도는 **진단 로그**에서 확인할 수 있습니다.

자세한 계산은 [타이밍 안내](docs/TIMING.md), 원본 출처와 구성은 [출처 안내](NOTICE.md)를 참고하세요.
